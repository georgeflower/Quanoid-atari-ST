# QUANOID

A native Atari ST brick-breaker, built in 68000 C and assembly. It runs on
Atari ST systems including the 520ST and 1040STFM, and has also been tested
with Hatari. The game uses its own interrupt-driven input and sound rather
than relying on TOS timing.

## Status

Playable end to end, with a title screen, level progression, paddle and ball
physics, power-ups, enemies, bosses, pause, high-score entry, and a
level-complete/exit-door mechanic. Available release executables and floppy
images are in [`releases/`](releases/).

## Gameplay

- **Bricks**: standard, multi-hit (shown with pip dots for hits remaining),
  and indestructible.
- **Enemies**: cube, sphere and pyramid types that spawn during play (max 3
  on screen at once, replaced only once defeated or on level clear — no
  timeout), each colour-coded, with a "low HP" tint when nearly destroyed.
- **Bosses**: wireframe 3D bosses (cube / sphere / pyramid / hexagon "mega
  boss") with aimed shots, lasers, 8-way bursts, spiral and cross attacks.
- **Power-ups** (capsules drop from bricks, caught by the paddle):
  | Letter | Effect |
  |---|---|
  | M | Multi-ball |
  | T | Turret (paddle-mounted shots) |
  | F | Fireball |
  | + | Wider paddle |
  | - | Narrower paddle |
  | S | Shield |
  | B | Barrier |
  | +1 | Extra life |
  | ? | Exit door (see below) |
- **Exit door**: if a level runs 60+ seconds with 3 or fewer indestructible
  bricks left and no life lost, a "?" capsule drops. Catching it opens a
  blinking-arrow exit on the right edge of the playfield, in line with the
  paddle, letting you skip to the next level. A HUD countdown shows the
  60-second timer once it starts.
- Losing a life resets every active power-up (ball/paddle size, shield,
  barrier, turret ammo, fireball).
- Pause (ESC) and level-complete both show big blocky Atari-style text.
- High-score entry is confirmed with Enter only (no mouse-click-away).

## Building

Cross-compiled with the Ubuntu `m68k-linux-gnu-gcc` toolchain, targeting a
real 68000 (`-m68000 -mstrict-align -fno-store-merging`, custom `math.S`
replacements for 68020-only mul/div instructions libgcc would otherwise
emit). A Python-based ELF→Atari PRG converter (`tools/elf2prg.py`) handles
GEMDOS relocation.

```sh
make            # builds build/QUANOID.PRG (release) and build/QUANTEST.PRG (autopilot test build)
```

Other targets (`QMICRO.PRG`, `QSNDDG.PRG`, `QEXITA.PRG`, etc.) are
diagnostic/benchmark builds used during development — see the `Makefile`.

`src/main.c`, `src/levels.h`, `src/font.h` and `src/sfx.h` are generated by
the `tools/` scripts (`assemble.py` concatenates the game source, `genlevels.py`
compiles `tools/levels.txt` into brick layouts, `genfont.py`/`gensfx.py`
generate the bitmap font and sound-effect tables) and are rebuilt
automatically by `make`.

## Running

To build a 720 KB floppy image named for a PR, install `mtools` and run, for
example, `make releases/qnoid003.st`. This updates both the root executable
and `AUTO/QUANOID.PRG`, which runs automatically when the floppy boots.

Copy `build/QUANOID.PRG` to a TOS-bootable disk image or hard drive folder and
launch it, or run it under [Hatari](https://hatari.tuxfamily.org/) with a
TOS/EmuTOS ROM:

```sh
hatari --tos /path/to/tos.img --auto build/QUANOID.PRG
```

Video uses the standard 320x200 display, without overscan. The space
background and hardware border are black; brick and paddle shading still use
raster colours. The next page's address is queued before the ST's pre-VBL
address latch; the VBL handler acknowledges the live Shifter address before
the old page is reused. Raster tables are built separately from the table
currently being displayed. Mouse and system-timer handlers allow raster
interrupts to preempt them.
Some paddle-shading line artifacts can still occur under controller load.

The on-screen version identifies the release or pull request build, with a
suffix for revised disks. See the filenames in [`releases/`](releases/) for
the release builds included in this repository. LEVEL and LIVES sit below a
dedicated boss-HP/exit-counter slot; the four power-up lines remain above the
footer.

The title includes the Qumran credit and animated capsules. Select START GAME
or INSTRUCTIONS with the arrow keys or joystick, then press Enter, Space or
fire. `I` opens instructions directly; Escape quits from the title.
Instructions show all nine capsule images and their effects. Escape, Enter,
Space or fire returns to the title.

Balls freeze during the boss-defeat countdown before the existing level
transition. The level-10 sphere returns light red in its second phase.
Boss animations use 32 frames per turn. The sphere and pyramid spin around
Y at a fixed viewing tilt, showing all four pyramid sides but not its bottom.
The sphere has rotating shading and highlights;
the fourth boss rotates around Z and Y. The pyramid is rendered 10% larger.
Its phases are purple, blue, light red, orange and white (including
resurrections); the fourth boss changes from gold to blue to light red.
Its sprite canvas is expanded to prevent clipping during rotation.
Spheres have smooth,
round silhouettes without detached shading pixels.
Run `python3 tools/test_gensprites.py` to check rotation and sphere masks.

During play, `T` toggles trainer mode. Up advances one level and Down goes
back one level (without wrapping at the first or last level). The HUD shows
`TRAIN` while enabled and `NO HI` after switching it off. Pressing `T`
disables high-score entry for the entire current game; starting a new game
resets trainer mode and restores high-score eligibility.

Ball movement skips empty enemy checks and brick checks outside the brick
area or on brick-free boss levels. This reduces missed display refreshes
without changing ball speed, collision stepping or the 50 Hz display limit.

Losing a life clears boss shots, bombs, lasers and queued attacks before
the next launch. Cross projectiles keep descending at least half a pixel
per game frame instead of slowing to a stationary obstacle.

## Source layout

- `src/main_head.c` — core types, system-call wrappers, screen/sprite
  primitives, dirty-rectangle rendering
- `src/game_part.c` — game state machine, level/brick/paddle/ball logic,
  power-ups, HUD, `main()`
- `src/boss_part.c` — boss AI, wireframe 3D rendering, attack patterns
- `src/enemy_part.c` — enemy spawning/AI, 8×8 sprite art, pre-shifted sprite
  tables for fast blitting
- `src/ikbd.S` — custom IKBD + Timer C interrupt handler (own mouse/
  keyboard/joystick and sound timing, independent of TOS's own vectors)
- `src/blitfast.S`, `src/gfx.S`, `src/math.S`, `src/sys.S`, `src/crt0.S` —
  assembly blitter, line/rect drawing, 68000-safe math, syscalls, startup

## Hardware requirements

- CPU: Motorola 68000 @ 8 MHz (including the Atari 520ST and 1040STFM; no
  68020 assumptions)
- Video: 320×200, 4 bitplanes (16 colours)
- Sound: YM2149 (PSG), 3 voices, driven directly rather than through TOS's
  Dosound/Timer C routine
- Input: custom IKBD interrupt handler for mouse and keyboard
